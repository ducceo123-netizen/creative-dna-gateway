# Visual brand acceptance — independent of technical QA

Select the same page archetype and goal before comparing. A minimal personalization form cannot validate an ecommerce PDP; a landing hero cannot validate a collection. Inventory reference home/collection/PDP/editorial/help as applicable, and compare at least two distinct relevant archetypes before claiming reusable system coverage. Record which are untested. A few matched tokens, a clean axe scan or an invented numerical score cannot establish brand fidelity.

## Extract beyond token values

For each archetype record the visual reading order and content density; dominant image position/area/aspect; column proportions, container and gutters; typography role hierarchy (including compact commerce titles versus display copy); header/nav/search; price/rating/offer/assurance placement; component anatomy, states, border/radius/icon treatment; contextual spacing. Record measured geometry at each viewport, not an assumed universal spacing scale. Include labels, spans, images, containers, computed styles and ancestors; hidden radio inputs and offscreen carousel items are not visible specimens.

Inspect imagery and banners directly. Describe subject relationships, product/name legibility, scene/lighting, palette treatment, text-safe area, crop/focal point and mobile asset changes. Compare actual desktop/mobile image URLs and pixels. Separate embedded image lettering from UI font. Seasonal red/green, category-specific imagery and common ecommerce structure are not automatically permanent brand DNA. Use at least one evergreen surface to qualify campaign conclusions.

## Compare and iterate

Save source and implementation screenshots with identical viewport and comparable state/scroll, both full page and corresponding crops. View them together. Write a discrepancy table: dimension, source evidence, implementation evidence, discrepancy, correction or deliberate adaptation, remaining uncertainty. Fix materially wrong archetype, composition, hierarchy and imagery before polishing minor tokens. Render again and inspect the changed regions. Preserve the first comparison and change log.

Required dimensions: archetype, composition-density, imagery-art-direction, typography-hierarchy, semantic-color, spacing, components-states, merchandising-copy, responsive-art-direction. Each has evidence paths and status aligned / deliberate-adaptation / mismatch / unknown / untested. These are explicit review judgments, not objective certification. Do not mark aligned merely because CSS values match. Explain accessibility adaptations separately and retain original measurements.

## Reusable package

Deliver a human brand manual, semantic + component tokens (not just a flat palette), image/banner art-direction examples, component specimens with observed versus proposed states, and page composition recipes. For primary/secondary/neutral/accent distinguish operational role observed on site from official corporate designation; use unknown when designation isn't supported. Functional success/error/warning colors are a separate family. Spacing/radius/border values need contextual roles and provenance. Proposed normalization must not masquerade as extracted source code.

G-visual and G-technical are separate. A pilot can be useful with deliberate adaptations and untested pages, but does not become a brand-approved system until its visual gaps and owner feedback are resolved. Preserve owner rejection as evidence of unresolved acceptance, not as a request to produce a higher score. No promise that arbitrary future pages will automatically be correct.
