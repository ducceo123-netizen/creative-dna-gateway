# Onepage feedback-first delivery

As of 2026-10-22, Onepage returns actual content and original assets in chat with the existing Feedback Onepage flow, not a hosted web preview. The compiler and template manifests retain their compatibility keys `onepage_preview_contract` / `live_html_feedback`, but advertise `CHAT_OUTCOME_WITH_GROUPED_FEEDBACK` and `hosted_url_required: false`. There is no default hosted publication contract or completion gate.

1. Complete existing research, product inspection, creative quality and content approval gates. Return content in chat before assets exist; do not offer nonexistent image targets.
2. Bind approved copy and actual assets into the selected canonical GTK/FAQ HTML/CSS for internal desktop/mobile visual QA. Preserve layout, required overall PNG mapping and production asset standards. Packaging still requires the owner's explicit request and real ZIP validation.
3. Show the actual current numbered/named asset inventory in chat. Offer the existing `/onepage-panel.html` Feedback Onepage tab with select/group/write/copy/paste instructions, or accept direct chat feedback. The generic copy-only panel receives no private task data or images and dispatches nothing.
4. Bind pasted groups to the current exact task or explicit outcome identity, revision and actual inventory. For registered tasks, resolve against the current review index. Unregistered outcomes use host-verified direct chat against their explicit outcome identity, version and actual inventory, not the task-only review-index tool. Stop on stale, missing or ambiguous mappings. Keep groups separate and unrelated approved content untouched. Do not invent a registered task ID.

Existing element-feedback runtimes, packagers and URLs are retained for compatibility, not used as the default delivery. A legacy packet must additionally match the current render hash, element and asset mappings. Downloaded documents cannot establish current task freshness. Do not automatically publish or generate web previews, send feedback, create queue entries, approve or Train.

This change affects delivery only. It does not change canonical design/content, source evidence requirements, asset sizes, GTK/FAQ selection, QC, production files or existing outcomes. LDP delivery remains separate.
