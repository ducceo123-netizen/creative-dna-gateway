# UID workspace release gates

This is a release checklist for the parallel web workspace, not an activation script. The existing ChatGPT/MCP flow remains a separate supported path. Local fixtures, a configured function, or an operator's `reviewed: true` field do not prove a release gate.

## Implemented locally

- Authenticated per-member tasks/actions/events, durable state and immutable snapshots, explicit content/artwork approvals, private reference upload, scoped mixed feedback and before/after history.
- React/Polaris workspace, direct preview element selection, desktop/mobile rendering contracts and actual verified file/ZIP download logic.
- Real canonical binding and packaging code, public source custody, semantic research orchestration, text/image/vision transports, independent QC records and a composed nine-stage worker pipeline.
- One shared project/member/task budget journal, named child-operation accounting, cancellation/revocation/lease checks and unknown-outcome fences.
- Read-only reconciliation of already-retained artifact bytes. This does not resolve an unknown provider charge or recover lost generated output.

## Engineering and verification still required

These are not solved merely by receiving an API key or user approval:

1. **General source coverage.** The supplied inventory adapter covers retained static HTML with a reviewed exact-document policy. It does not execute arbitrary product scripts, inspect dynamic galleries or play videos. A normal Shopify PDP/collection cannot be assumed supported. Add and verify a concrete platform/browser integration for the intended product sources; retain original product/variant/media identity and honest partial coverage. Search/discovery and social/video inspection also need actual authorized adapters. Never fabricate completion to bypass canonical research gates.
2. **Actual browser acceptance.** Run the new UI on a supported browser, including Vietnamese IME, login interruption, reload, repeated clicks, newer navigation, direct selection, stale revisions, desktop/mobile preview and private downloads. Capture actual rendered Onepages at all four required viewports. Existing mocked browser tests do not satisfy this.
3. **Live data-store proof.** Reconcile the owner-state/budget/login design with the existing disabled checkpoint foundation. Review exact roles, tables, RPC ownership and storage limits. Test real PostgreSQL transactions from separate connections, RLS, membership revocation, restart, lost commit acknowledgement and retained accounting fences.
4. **Image cost and geometry.** Verify the actual account's model/endpoint capabilities and current pricing. Supply a defensible exact-request image cost upper bound or reviewed bound resolver. The pure sizing planner now derives exact-ratio numeric proposals from byte-pinned canonical templates, without inventing approval. Four icon slots remain blocked: responsive percentage widths and unspecified intrinsic geometry do not prove one exact 3× display size. Resolve the display envelope/aspect policy and retain actual reviewed evidence. A generic guessed per-image price or silent crop/stretch is not accepted.
5. **Recovery.** Implement and review provider-specific read-only reconciliers where the provider offers conclusive output/usage evidence. Lost Images responses or unavailable stored Responses may remain manual accounting cases. Never retry them merely because a timeout or 404 occurred.
6. **EO evidence.** Select current-canonical approved golden cases, pin source bytes/policy/template/approved output, run the permitted candidate, and evaluate product fidelity, supported claims, real pixels, typography and blind human preference. The goal is better than the current outcome, but improvement and no-regression are unproven until those comparisons pass. Historical references with outdated mobile-title policy are not current canonical goldens.
7. **Repository/release hygiene.** Reconcile Trustpilot PR125 with the exact new main, rerun affected research and legacy MCP checks, validate the intended clean package-manager install, resolve the official Polaris Web Components production-license question, and review the assembled branch. No draft PR, merge, deploy or production-ready claim substitutes for these checks.

## Decisions/authorization the operator must obtain

Collect concrete values/targets instead of asking for a broad permission to "enable everything":

- **API project and money:** the intended OpenAI project; one-time or monthly total cap; per-member, per-task and per-request caps; approved benchmark allowance and expiry. Verify current balance separately. Shared key use does not imply unlimited spend, and ChatGPT subscription/credits do not automatically enable this API project.
- **Secure credential provisioning:** an authorized secure handoff to the chosen server/worker secret store. Do not paste keys into chat, source code, browser bundles or logs. Setting up persistent access requires the appropriate action-time approval.
- **Database/storage/auth deployment:** after the engineering review resolves exact resources, present the specific additive schema/roles/RPCs, private bucket media/size changes, existing membership/login integration and worker service for approval. No public bucket, signup, broad service-role credential or change to the existing ChatGPT execution path is assumed.
- **Source/processor scope:** the intended storefronts and any private source/reference data allowed to be processed by the configured providers. Public business/product evidence is not permission to upload unrelated private material.
- **Browser environment:** use an existing permitted browser runtime. Installing a new local runtime or browser requires the applicable approval; an unavailable helper or denied sandbox action does not authorize a bypass.

User interface readiness must distinguish missing configuration, unsupported product/source capability, pending evidence, known failure and unknown outcome. The app may save an authorized brief while execution remains blocked. No fixture output is a substitute for a real user task.
