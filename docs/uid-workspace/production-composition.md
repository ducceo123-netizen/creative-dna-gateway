# Onepage production composition

`createWorkspaceOnepageProductionPipeline(services, options)` is the concrete pipeline for the existing `WorkspaceRuntimeConfig.createPipeline` hook. It wires:

1. Authorized, retained public source captures through the run's private artifact journal.
2. Research extraction, actual-image inspection and evidence-backed content planning through individually budgeted child calls.
3. Optional reviewed static-document browser inventory with separately reopenable DOM/screenshot evidence. Dynamic/unknown themes cannot be silently declared complete.
4. Sol text authoring, separate independent vision QC, and exact user content approval.
5. Real per-slot Images API edits using retained product pixels and approved copy; selected feedback begins with the exact original image. Reviewed same-aspect downscaling handles provider/canonical dimensions. No crop/stretch/pad or guessed icon size.
6. Fixed canonical rendering at desktop/mobile/breakpoints; separate independent pixel/semantic review and actual user artwork approval.
7. Real ZIP construction/reopening and private package delivery.

The factory also connects the durable QC registry, original-source evidence resolver, artifact writer and per-stage deadlines. It creates no account, credential, data grant, live database object, browser process, network request or worker on construction. Importing it is not permission to execute or a release certification.

## What must be configured and verified

- Existing authenticated membership, owner-isolated database state, shared budget table, private object custody, narrow worker role and reviewed ingress login protection.
- Server-only credentials and currently verified text, vision and image capabilities in the same approved API project. Strict reviewer structured-output support is required. The factory does not use a ChatGPT login/session as API credentials.
- Explicit project/member/task/request spend grants and processor/data authorization. Text/image/vision share the same journal and caps. There is no installed image cost-bound estimate; an independently defensible bound or reviewed bound algorithm is mandatory before image dispatch.
- Current pinned UID canonical resolver and actual permitted source origins. Discovery/search is an explicit external capability; unavailable social/video routes are recorded honestly, not replaced with imagined findings.
- A reviewed browser launcher and source-theme enumeration policy. The shipped inventory adapter covers retained static/pre-rendered pages only. Real dynamic gallery/variant coverage still needs an audited platform/browser integration.
- Current reviewer authority and verified per-slot fitting strategies, including actual canonical icon display dimensions. These are code/operator review facts, not model-provided booleans.
- Permitted real-browser UI/IME/pixel tests, live database concurrency/restart tests, current account/pricing access, and the actual blinded EO benchmark against a current canonical baseline.

## Recovery boundary

Unknown provider outcomes do not generate again automatically. The operation journal retains every request and reservation; the API enables recovery only when a reviewed provider-specific reconciler is installed. `services.reconcileArtifactWrites` can reopen and checksum already-retained immutable objects under the current recovery fence without PUT/deletion or provider calls. It does not prove billing settlement, no-side-effect, stage completion or QC. Missing bytes remain unknown. Responses with unavailable server output and Images requests whose final response was lost may require operator billing reconciliation. Do not fake a successful resume from a timeout/404.

## Validation interpretation

Unit/integration fixtures exercise real byte handling, request encoding, canonical binding, ZIP construction and journal transitions. They do not prove production database isolation, current API entitlement, actual charges, real browser appearance or better EO. Keep execution disabled until those independent release gates are met. The existing ChatGPT/MCP path is unchanged.
